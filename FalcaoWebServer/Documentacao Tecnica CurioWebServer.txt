==================================================
COMPONENTES ANALISADOS
==================================================

1. AUTHCONTROLLER.CS
--------------------------------------------------
LOCALIZAÇÃO: Controllers/AuthController.cs
RESPONSABILIDADE: Gerenciar todo o ciclo de autenticação e autorização

ENDPOINTS PRINCIPAIS:
- POST /api/auth/login: Autenticação inicial com email/senha
- POST /api/auth/cadastrousuario: Registro de novos usuários
- POST /api/auth/verifypin: Validação de PIN de segurança
- POST /api/auth/resendpin: Reenvio de PIN por email
- POST /api/auth/refreshtoken: Renovação de tokens
- POST /api/auth/logout: Logout seguro
- POST /api/auth/changepassword: Alteração de senha

CARACTERÍSTICAS DE SEGURANÇA:
- Refresh tokens armazenados em cookies HttpOnly
- Validação de PIN numérico com expiração
- Proteção contra brute force com bloqueio automático
- Tokens de acesso com tempo limitado (15 minutos)

FLUXO DE AUTENTICAÇÃO:
1. Login com email/senha → Gera PIN e envia por email
2. Validação do PIN → Ativa usuário e gera tokens
3. Refresh automático via cookie HttpOnly
4. Logout revoga tokens e limpa cookies

2. AuthManager.CS
--------------------------------------------------
LOCALIZAÇÃO: Services/AuthManager.cs
RESPONSABILIDADE: Lógica de negócio para autenticação e gestão de tokens

FUNCIONALIDADES PRINCIPAIS:
- Validação de credenciais de usuário
- Geração de tokens JWT e refresh tokens
- Gestão de refresh tokens no banco de dados
- Bloqueio automático após múltiplas tentativas falhas
- Validação de tokens de acesso

MÉTODOS CRÍTICOS:
- ValidateUserByEmailAsync(): Valida email/senha e gerencia bloqueios
- GenerateTokensAsync(): Gera par de tokens JWT + refresh
- SaveRefreshTokenAsync(): Persiste refresh token com hash seguro
- RevokeRefreshTokenAsync(): Revoga tokens para logout

SEGURANÇA:
- Senhas armazenadas como SHA256
- Refresh tokens com hash antes de persistir
- Validação de expiração em todos os tokens
- Cache para controle de tentativas falhas

3. TOKENSERVICE.CS
--------------------------------------------------

FUNCIONALIDADES:

CONFIGURAÇÃO:

==================================================
FLUXOS DE NEGÓCIO PRINCIPAIS
==================================================

1. FLUXO DE AUTENTICAÇÃO:
   → Usuário envia email/senha para /api/auth/login
   → Sistema valida credenciais e gera PIN
   → PIN enviado por email via IEmailService
   → Usuário valida PIN em /api/auth/verify-pin
   → Sistema ativa usuário e gera tokens JWT
   → Refresh token armazenado em cookie HttpOnly
   → Access token retornado para cliente

2. FLUXO DE PEDIDO DE VENDA:
   → Usuário cria rascunho via /api/PedidoVenda/Draft
   → Itens salvos temporariamente no banco
   → Confirmação via /api/PedidoVenda/Confirm
   → Geração automática de PDF via PedidoVendaRelatorioService
   → Envio automático de email para cliente/vendedor
   → Persistência do caminho do PDF no pedido

3. FLUXO DE CRUD GENÉRICO:
   → Cliente chama endpoints dinâmicos (/api/{entity})
   → GenericCrudController descobre tipo da entidade
   → GenericCrudService executa operação no banco
   → Mapeamento automático DTO → Entity quando aplicável
   → Retorno padronizado com paginação

CONFIGURAÇÕES E VARIÁVEIS DE AMBIENTE
==================================================

VARIÁVEIS OBRIGATÓRIAS (prefixo CURIO__):
- DB:DefaultConnection: String de conexão MySQL
- JWT:Key: Chave secreta para tokens JWT
- JWT:Issuer: Emissor dos tokens
- JWT:Audience: Audience dos tokens
- EMAIL:HOST: Servidor SMTP
- EMAIL:PORT: Porta SMTP
- EMAIL:USER: Usuário SMTP
- EMAIL:PASSWORD: Senha SMTP

CONFIGURAÇÕES OPACIONAIS:
- ADMIN__EMAIL: Email do usuário admin
- ADMIN__USERNAME: Nome do usuário admin
- ADMIN__PASSWORD: Senha do usuário admin
- APP:EnableSwagger: Habilitar Swagger em produção
- STORAGE:RelatoriosPath: Caminho para salvar PDFs
