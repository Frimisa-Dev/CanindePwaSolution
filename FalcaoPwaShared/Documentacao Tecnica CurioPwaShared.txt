==================================================

==================================================
MODELOS DE AUTENTICAÇÃO (Models/Auth/)
==================================================

1. USER.CS
--------------------------------------------------
RESPONSABILIDADE: Representar um usuário do sistema

PROPRIEDADES:
- Id: Identificador único (auto-increment)
- Username: Nome de usuário
- Email: E-mail único para login
- PasswordHash: Hash SHA256 da senha
- IsLocked: Indica se usuário está bloqueado
- IsActive: Indica se usuário está ativo/validado
- CreatedAt: Data de criação
- LastLoginAt: Data do último login
- UserRoles: Coleção de roles do usuário

USO: Backend (Entity Framework) e Frontend (estado da aplicação)

2. ROLE.CS
--------------------------------------------------
RESPONSABILIDADE: Representar uma permissão/nível de acesso

PROPRIEDADES:
- Id: Identificador único
- Name: Nome da role (Admin, User, etc.)
- Description: Descrição da role

USO: Sistema de autorização baseado em roles

3. USERROLE.CS
--------------------------------------------------
RESPONSABILIDADE: Tabela de junção para relação N:N entre User e Role

PROPRIEDADES:
- UserId: Chave estrangeira para User
- RoleId: Chave estrangeira para Role
- Role: Navegação para a Role

USO: Mapeamento Entity Framework para relação muitos-para-muitos

4. REFRESHTOKEN.CS
--------------------------------------------------
RESPONSABILIDADE: Gerenciar tokens de refresh para autenticação persistente

PROPRIEDADES:
- Id: Identificador único
- UserId: Usuário dono do token
- TokenHash: Hash do token (armazenamento seguro)
- ExpiresAt: Data de expiração
- CreatedAt: Data de criação
- RevokedAt: Data de revogação (logout)
- CreatedByIp: IP de origem
- Purpose: Finalidade do token (null para auth, "email_confirmation" para confirmação)
- ReplacedByTokenHash: Token que substituiu este

USO: Backend para gestão segura de refresh tokens

5. EMAILPIN.CS
--------------------------------------------------
RESPONSABILIDADE: Gerenciar PINs de verificação por email

PROPRIEDADES:
- Id: Identificador único
- UserId: Usuário associado
- Code: PIN numérico de 6 dígitos
- ExpiresAt: Data de expiração (10 minutos)
- Used: Indica se já foi utilizado
- User: Navegação para o usuário

USO: Fluxo de verificação de email e ativação de conta

==================================================
DATA TRANSFER OBJECTS (Models/Dtos/)
==================================================

📌 DTOs DE AUTENTICAÇÃO:

1. LOGINDTO.CS
--------------------------------------------------
RESPONSABILIDADE: Transportar credenciais de login

PROPRIEDADES:
- Email: E-mail do usuário (required)
- Password: Senha do usuário (required)

USO: Request do Frontend para Backend no login

2. LOGINRESPONSEDTO.CS
--------------------------------------------------
RESPONSABILIDADE: Transportar resposta do login

PROPRIEDADES:
- AccessToken: Token JWT de acesso
- RefreshToken: Token para renovação
- Success: Indica sucesso da operação
- Message: Mensagem descritiva
- RequiresPin: Indica se requer verificação de PIN
- Email: E-mail do usuário
- Username: Nome do usuário
- ExpiresIn: Tempo de expiração em segundos

USO: Response do Backend para Frontend

3. CadastroUsuarioDto.CS
--------------------------------------------------
RESPONSABILIDADE: Transportar dados de registro

PROPRIEDADES:
- Username: Nome de usuário (required)
- Email: E-mail (required)
- Password: Senha (required)
- ConfirmPassword: Confirmação de senha (required)

USO: Request para criação de novo usuário

4. VERIFYPINDTO.CS
--------------------------------------------------
RESPONSABILIDADE: Transportar dados de verificação de PIN

PROPRIEDADES:
- Email: E-mail do usuário (required)
- Code: PIN de verificação (required)

USO: Validação de PIN enviado por email

5. AUTHRESPONSE.CS
--------------------------------------------------
RESPONSABILIDADE: Resposta genérica de autenticação

PROPRIEDADES:
- AccessToken: Token JWT
- RefreshToken: Token de refresh
- ExpiresAt: Data de expiração

USO: Padrão de resposta para operações de auth

📌 DTOs DE NEGÓCIO:

6. PEDIDOVENDACAPADTO.CS
--------------------------------------------------
RESPONSABILIDADE: Transportar dados de capa de pedido de venda

PROPRIEDADES:
- ID_PessoaCliente: Cliente do pedido
- ID_PessoaVendedor: Vendedor responsável
- ID_Prazo: Condição de pagamento
- NumeroPedido: Número único do pedido
- DataPedido: Data de emissão
- DataPrevisaoEntrega: Data prevista para entrega
- TotalPedidoVenda: Valor total
- Comissao: Percentual de comissão
- ValorComissao: Valor da comissão
- SituacaoPedidoVendaCapa: Situação do pedido (enum)
- Items: Lista de itens do pedido

USO: Criação e edição de pedidos de venda

7. PEDIDOVENDAITEMDTO.CS
--------------------------------------------------
RESPONSABILIDADE: Transportar dados de item de pedido

PROPRIEDADES:
- ID_PedidoVendaItem: Identificador do item
- ID_Usuario: Usuário que criou o item
- ID_Produto: Produto vendido
- ID_Cor: Cor do produto
- ID_TipoCalcado: Tipo de calçado
- Bico: Tipo de bico
- QuantidadePedida: Quantidade total
- PrecoItem: Preço unitário
- TotalItem: Valor total do item
- Campos Nro01-Nro15 e Qte01-Qte15: Tamanhos e quantidades

USO: Gestão de itens de pedido com sistema de tamanhos

8. PESSOADTO.CS
--------------------------------------------------
RESPONSABILIDADE: Transportar dados completos de pessoa (cliente/fornecedor)

PROPRIEDADES:
- TipoPessoa: "Fisica" ou "Juridica" (com validação)
- Cpf/CNPJ: Documento com validação de formato
- Nome/RazaoSocial: Nome completo
- Cep: CEP com validação de formato
- Endereço completo: Logradouro, Bairro, Cidade, etc.
- Contatos: Telefone, email com validações
- Perfil: Tipo de perfil
- Comissao: Percentual para vendedores
- Estatus: Situação no sistema

USO: Cadastro unificado de pessoas

MODELOS DE VIEWS (Models/Uvw/)
==================================================

📌 PRINCÍPIO: Modelos para consultas otimizadas (ReadOnly)

1. UVWPEDIDOVENDACAPA.CS
--------------------------------------------------
RESPONSABILIDADE: View unificada com dados completos do pedido

CARACTERÍSTICAS:
- JOINs com tabelas de pessoa (cliente, vendedor)
- Dados de endereço completos

--------------------------------------------------
RESPONSABILIDADE: View unificada com dados completos dos itens

CARACTERÍSTICAS:

- Dados descritivos além dos IDs
- Mantém estrutura de tamanhos da tabela

3. UVWPESSOA*.CS
--------------------------------------------------
RESPONSABILIDADE: Views especializadas para cada tipo de pessoa

VARIANTES:
- UvwPessoa: View geral de pessoas
- UvwPessoaCliente: Dados específicos de clientes
- UvwPessoaVendedor: Dados específicos de vendedores
- UvwPessoaFornecedor: Dados específicos de fornecedores

==================================================
PADRÕES E CONVENÇÕES
==================================================

NOMENCLATURA:
- *: Modelos de tabelas (CRUD)
- Uvw*: Modelos de views (ReadOnly)
- *Dto: Data Transfer Objects
- ID_*: Chaves primárias
- PascalCase: Todas as propriedades

VALIDAÇÕES:
- DataAnnotations em DTOs
- Enums com conversão string para MySQL
- Validações de formato (CPF, CNPJ, CEP, Email)

MAPEAMENTO:
- Entity Framework no Backend
- JSON Serialization no Frontend
- Enums como strings no banco

==================================================
FLUXO DE DADOS ENTRE CAMADAS
==================================================

BACKEND → SHARED → FRONTEND:
1. Backend usa * para operações de banco
2. Backend transforma * em DTOs para API
3. DTOs trafegam via JSON para Frontend
4. Frontend usa DTOs para estado da aplicação

CONSULTAS:
1. Backend consulta Uvw* para relatórios
2. Uvw* retornam dados unificados prontos
3. Frontend recebe dados formatados

==================================================
BENEFÍCIOS DA ARQUITETURA
==================================================

CONSISTÊNCIA:
- Mesmos modelos no Backend e Frontend
- Validações centralizadas
- Tipagem forte em toda aplicação

MANUTENIBILIDADE:
- Alterações em um local afetam toda aplicação
- Contratos bem definidos entre camadas
- Código duplicado eliminado

SEGURANÇA:
- DTOs com validações preventivas
- Separação entre modelos de persistência e transferência
- Controle de what é exposto via API

PERFORMANCE:
- Views otimizadas para consultas
- DTOs com apenas dados necessários
- Redução de chamadas de API
